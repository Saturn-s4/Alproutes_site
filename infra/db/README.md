# База данных

Миграции Flyway — `migration/`, файлы после мержа не меняются. Любое изменение схемы — новый `V<N>__*.sql`.

| Миграция | Что внутри |
|---|---|
| V1 | Расширения (PostGIS, pg_trgm, citext), общие функции: `updated_at`, проверка `LocalizedText`, защита append-only |
| V2 | Пользователи, OAuth-идентичности, refresh-токены с ротацией |
| V3 | Системы категорий и справочник допустимых значений |
| V4 | Районы: иерархия, точка, высота вершины, контур; защита от циклов |
| V5 | Маршруты и ревизии — полные снимки, одна текущая |
| V6 | Восхождения, состав группы, комментарии |
| V7 | Загрузки в S3, фото, прорисовки нитки, треки, архивные PDF |
| V8 | Жалобы и журнал модерации |
| V9 | Геометрия маршрута: произвольный набор точек и 2D-линий в ревизии, кэш `route_geo` для геопоиска |

## Принципы, которые держит сама БД

- **Ревизии и прорисовки не редактируются и не удаляются** — триггер `enforce_append_only`. Меняться могут только поля модерации. Откат — новая ревизия-копия.
- **Одна текущая ревизия на маршрут** — частичный уникальный индекс. Поиск по названию тоже по частичному индексу (`WHERE is_current`).
- **Геометрия маршрута** — любой набор объектов ревизии: точки `start`, `summit`, `bivouac`, `descent_start` и линии `route_line`, `approach`, `descent`, в том числе ни одного. Только 2D, вид объекта обязан совпадать с типом геометрии. Линию можно импортировать из трека того же маршрута — геометрия копируется, трек сохраняется как источник.
- **Геопоиск** идёт по `route_geo` — кэшу геометрии текущей ревизии, который триггер обновляет при публикации. Точка маркера: начало → вершина → первая точка нитки → любой другой объект.
- **Категории** — только значения из `grade_values`, не больше одной на систему. Латинская «5B» вместо «5Б» отклоняется.
- **Документ нельзя опубликовать** без проверенного правового статуса — ограничение `documents_visible_requires_cleared_rights`.
- **Фото и трек восхождения** обязаны относиться к тому же маршруту, что и восхождение (составной внешний ключ).
- **Пользовательский контент** создаётся с `id` от клиента (идемпотентная офлайн-синхронизация) и удаляется мягко (`deleted_at`), чтобы удаление дошло до офлайн-копий.
- **NULL = нет данных.** Значений по умолчанию для фактов о маршрутах нет.

## Тесты схемы

```bash
docker compose -f infra/docker-compose.yml up -d db
docker compose -f infra/docker-compose.yml run --rm flyway migrate
docker compose -f infra/docker-compose.yml exec db psql -U alproutes -d alproutes -v ON_ERROR_STOP=1 -f /db-tests/constraints_test.sql
docker compose -f infra/docker-compose.yml exec db psql -U alproutes -d alproutes -v ON_ERROR_STOP=1 -f /db-tests/postgis_test.sql
```

Оба файла всё откатывают в конце. Последняя строка вывода — `ALL ... TESTS PASSED`.
