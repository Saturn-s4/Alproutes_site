# Backend

Kotlin + Spring Boot 3.5, Spring JDBC (без JPA), PostgreSQL 16 + PostGIS, Flyway, S3 (SeaweedFS локально).
Контракт — `/shared/openapi.yaml`. DTO написаны вручную по контракту; соответствие проверяют интеграционные тесты.

## Запуск

```bash
docker compose -f infra/docker-compose.yml up -d db seaweedfs s3-init
cd backend && ./gradlew bootRun --args='--spring.profiles.active=dev'
```

API — `http://localhost:8080/api/v1`. Миграции из `/infra/db/migration` применяются при старте.

Вход в dev-профиле (без OAuth):

```bash
curl -s -X POST localhost:8080/api/v1/auth/dev-login \
  -H 'Content-Type: application/json' \
  -d '{"email":"mod@local","displayName":"Модератор","role":"moderator"}'
```

## Тесты

```bash
cd backend && ./gradlew test
```

Нужен Docker: тесты поднимают `postgis/postgis:16-3.4` и SeaweedFS через Testcontainers.

## Настройки (переменные окружения)

| Переменная | Назначение |
|---|---|
| `DB_URL`, `DB_USER`, `DB_PASSWORD` | Подключение к Postgres |
| `JWT_SECRET` | Ключ HS256 для access-токенов, ≥ 32 байт. Обязателен вне `dev` — без него сервер не стартует |
| `GOOGLE_CLIENT_IDS`, `APPLE_CLIENT_IDS` | OAuth client id через запятую. Пусто — вход через провайдера выключен |
| `CORS_ALLOWED_ORIGINS` | Разрешённые origin веб-клиента |
| `S3_ENDPOINT`, `S3_PUBLIC_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_REGION` | Хранилище. `S3_PUBLIC_ENDPOINT` — адрес, который попадёт в pre-signed URL (как его видит браузер) |
| `S3_PUBLIC_BUCKET`, `S3_PUBLIC_BASE_URL` | Публичный бакет для производных фото (EXIF вычищен) и его адрес для клиентов — в продакшене CDN |

Клиенты загружают файлы прямо в приватный бакет по pre-signed URL, поэтому на хранилище нужен CORS для origin веба (методы `PUT`, `GET`, заголовок `Content-Type`). SeaweedFS в `infra/docker-compose.yml` разрешает любой origin — для локальной разработки; в продакшене ограничить своим доменом.

## Что реализовано (шаг 2)

- Вход: Google/Apple ID token, dev-вход, refresh с ротацией и обнаружением повторного использования, выход, `/me`.
- Справочник категорий, районы (список, карточка, создание и изменение модератором).
- Маршруты: создание, правки с проверкой базовой ревизии, одобрение, отклонение, откат, история, очередь модерации, флаг `publish` для модераторов.
- Поиск: bbox по всем геообъектам, радиус от маркера, район с подрайонами, текст (триграммы), диапазон категорий, тип; курсорная пагинация для всех сортировок; точки для карты.
- Pre-signed URL для загрузки в S3.

## Фото и архивные PDF (часть шага 4)

- Фото маршрута: создание по `uploadId` (файл обязан реально лежать в S3 с заявленным размером), идемпотентно по `id` от клиента; список с фильтром `inDescription`, просмотр, правка подписи, мягкое удаление.
- Обработка фото — асинхронно после коммита: поворот по EXIF-ориентации, три размера JPEG (400 / 1280 / 2560 px) в публичный бакет `alproutes-public`, все метаданные вычищены. Время съёмки сохраняется, только если камера записала часовой пояс; GPS — в `photos.location`. Оригинал остаётся в приватном бакете. HEIC пока не поддерживается (`failed`).
- Фото описания — `RouteContent.photos`: список в ревизии (`route_revision_photos`, V10), версионируется и откатывается вместе с описанием. Остальные фото маршрута — галерея участников. `coverPhotoUrl` в выдаче — миниатюра первого фото описания.
- Документы: загрузка PDF (проверяется сигнатура `%PDF-`), создаются скрытыми; модератор ставит правовой статус и видимость (`PUT /documents/{id}/rights`), очередь — `/moderation/documents`. Скачивание — `302` на временную ссылку (`inline`), для непроверенных — `451`. Число страниц пока не считается (`pageCount = null`).

## Треки GPX/KML (часть шага 4)

- Загрузка по `uploadId`, идемпотентно по `id` от клиента; обработка асинхронно после коммита.
- Разбор — StAX с выключенными DTD и внешними сущностями (защита от XXE). GPX: треки, иначе маршруты (`rte`); KML: `LineString`, `gx:Track`. До 200 000 точек.
- Длина — по сфероиду (`geography`). Набор, сброс, мин/макс и профиль — по высотам, пересэмплированным через 10 м и сглаженным окном ±50 м, с порогом 3 м; сырые высоты не отдаются. Сверки с DEM пока нет, `elevationSource = null` (по файлу не определить, GPS это или барометр).
- Без высот: профиля нет (`404`), геометрия отдаётся в 2D — нулевая высота не выдаётся за настоящую.
- Импорт линии в маршрут (`sourceTrackId`) уже был в ревизиях; трек из нескольких несклеиваемых сегментов — `400 track-not-contiguous`.

Остальные эндпоинты контракта (прорисовки, восхождения, комментарии, жалобы, фото районов) пока отвечают `404`.
