# Web

Next.js 16 (App Router), TypeScript, MapLibre GL JS. Клиент API `/api/v1` backend на Kotlin, своей логики и БД нет.

## Запуск

```bash
docker compose -f infra/docker-compose.yml up -d db seaweedfs s3-init
cd backend && ./gradlew bootRun --args='--spring.profiles.active=dev'
cd web && npm install && npm run dev
```

Открыть `http://localhost:3000`. Вход — `/login`: локально dev-вход backend, при настроенном ключе — Google (см. ниже). Тестовые данные — `infra/dev-seed`.

## Вход через Google

Браузер получает у провайдера ID token, backend проверяет его подпись по ключам провайдера (`POST /auth/oauth/{provider}`) и выдаёт свою пару токенов. Пароли AlpRoutes не хранит. Переменные — в `.env.example` (веб) и `application.yml` (backend); кнопка появляется, только когда задан ключ.

**Google**
1. Google Cloud Console → APIs & Services → Credentials → Create OAuth client ID → тип **Web application**.
2. Authorized JavaScript origins: `http://localhost:3000` и адрес продакшена. Redirect URI не нужен (всплывающее окно).
3. Веб: `GOOGLE_CLIENT_ID=<id>`. Backend: `GOOGLE_CLIENT_IDS=<id>` (через запятую, если клиентов несколько — например, ещё Android).


Вход через Apple пока не подключён в вебе: backend его поддерживает (`APPLE_CLIENT_IDS`), но нужны Apple Developer Program и домен с HTTPS.

## Страницы

| Путь | Что | Рендер |
|---|---|---|
| `/` | карта: маршруты в области, панель маршрута | клиент |
| `/catalog` | каталог: фильтры (категории по системе, район, GPX/PDF) со счётчиками, сортировка; состояние в URL | SSR |
| `/areas/[slug]` | район: вложенные районы, маршруты | SSR |
| `/routes/[slug]` | маршрут: описание, фото, треки, архивные PDF, геометрия на карте, восхождения, обсуждение с фото, дисклеймер | SSR |
| `/routes/[slug]/history` | история правок | SSR + клиент |
| `/edit/routes/new`, `/edit/routes/[id]` | создание маршрута и правка (полный снимок ревизии) | клиент |
| `/edit/areas/new`, `/edit/areas/[id]` | районы (модераторы) | клиент |
| `/revisions/[id]` | ревизия: сравнение с базовой, одобрение / отклонение / откат | клиент |
| `/moderation` | очередь правок, прорисовок нитки и документов без проверки прав (модераторы) | клиент |
| `/login` | вход через Google; dev-вход при разработке | сервер (настройки) + клиент |

## Как устроено

- **Типы API** генерируются из `/shared/openapi.yaml` (`npm run gen:api`, запускается автоматически перед `dev` и `build`). Файл `src/lib/api/schema.d.ts` не коммитится. Запросы — через `openapi-fetch`, типизированный по этим типам.
- **Прокси.** Браузер ходит на `/api/v1/*` того же origin, Next проксирует на `API_URL` (`next.config.ts`). Серверные компоненты обращаются к `API_URL` напрямую.
- **SSR.** Каталог, районы и маршруты рендерятся на сервере ради индексации; формы, модерация и карта — клиентские. Фильтры каталога — обычные ссылки с параметрами: работают без JS.
- **Язык и тема** хранятся в cookie (`lang`, `theme`), чтобы сервер сразу рендерил нужный вариант. Тема: системная / тёмная / светлая.
- **Сессия** — пара токенов в `localStorage`, обновление access-токена в один поток (требование контракта).
- **Карта** — растровые тайлы OpenTopoMap. В тёмной теме они инвертируются paint-свойствами raster-слоя, а не CSS-фильтром, поэтому линии и точки сохраняют свои цвета. Воркер MapLibre копируется в `public/maplibre` (`npm run prepare:assets`): бандлер не умеет разрешать его путь сам.
- **Редактор геометрии** (`components/edit/GeometryEditor.tsx`) — свой, без библиотеки: точки и линии типов из контракта, перетаскивание, вставка вершины через середину отрезка, удаление правым кликом, ввод координат вручную (`lib/coords.ts`: десятичные градусы, градусы-минуты, DMS, буквы полушарий), линия из GPX/KML-трека.
- **Загрузка файлов** (`lib/upload.ts`) — по pre-signed URL прямо в S3, мимо backend; затем создаётся сущность с `uploadId`. Нужен CORS на хранилище для origin веба (SeaweedFS локально разрешает любой — в продакшене сузить).
- **Треки.** Статистика и профиль высот — только с сервера (сглаженные). В браузере GPX/KML читается (`lib/gpx.ts`) лишь чтобы взять линию в маршрут до его создания; файл после создания маршрута загружается к нему как трек.
- **Фото.** Фото описания (подписи из ревизии) и галерея участников (`inDescription=false`), полноэкранный просмотр — `Lightbox`. Картинки берутся напрямую из публичного бакета.
- **Нитка на фото** (`components/edit/TopoEditor.tsx`, `lib/topo.ts`) — свой редактор на SVG: штрих от руки прореживается до опорных точек (Douglas–Peucker), через них строится центростремительный сплайн Catmull–Rom — то же правило зафиксировано в контракте для Android. Тип линии и узор (сплошная, штрих, штрих-пунктир, точки, стрелка на конце), условные знаки из общего набора `shared/topo-symbols` (данные генерируются в `lib/topo-symbols.data.ts`) с подписью и поворотом, правка точек и знаков. Версии и модерация — как у ревизий маршрута.
- **Восхождения** (`components/Ascents.tsx`) — записи о восхождениях по маршруту, свежие сверху. Дата с точностью до дня, месяца или года (для давних восхождений), итог, группа, ходовое время, условия, отчёт, фото (загружаются после сохранения записи — фото ссылается на восхождение). Правка — полная замена записи (PUT). Приватная запись и её фото видны только автору.
- **Обсуждение** (`components/Comments.tsx`) — комментарии с ответами в один уровень. Фото к комментарию сначала загружаются к маршруту, потом комментарий забирает их по id; id генерируются один раз, так что повторная отправка после обрыва связи ничего не дублирует. Отдельной загрузки фото участников нет: галерея собирает фото из комментариев.
- **PDF** открываются встроенным просмотрщиком браузера в `iframe`: `/api/v1/documents/{id}/download` отвечает редиректом на временную ссылку. pdf.js понадобится для своего интерфейса просмотра (мобильные браузеры PDF в iframe показывают плохо).
- **Данные не додумываются.** Пустое поле формы уходит как `null` («нет данных»), категория без выбранного значения не отправляется, категории всегда показываются с системой.
- **Стили** перенесены из `web-prototype/src/styles` (варианты A и B).

## Зависимости

| Пакет | Зачем |
|---|---|
| `next`, `react`, `react-dom` | стек из CLAUDE.md |
| `maplibre-gl` | карта (CLAUDE.md: только MapLibre) |
| `openapi-fetch` | типизированный fetch по сгенерированным типам, ~6 КБ |
| `openapi-typescript` (dev) | генерация типов из контракта |

Внешний скрипт (не npm, грузится только на `/login` и только при настроенном ключе): Google Identity Services (`accounts.google.com/gsi/client`) — официальный клиент Google, без него ID token в браузере не получить.
